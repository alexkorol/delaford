## Phase 1 — Combat feel (P0, small-medium)

### 1a. Sprite flash on hit
`src/core/map.js` — monsters get a clean red tint rect for 200ms after
`lastHitAt` (~line 985). Find how the **player** sprite reacts when hit
(grep `lastHitAt|alpha|visible|blink` around the player draw path in

for monsters: never hide the sprite, only overlay `rgba(255,64,64,0.4)` for
150–200ms.
Accept: hit player sprite stays visible; brief tint only.

### 1b. Unarmed combat / retaliation
`server/core/combat/index.js` already rolls unarmed damage
(`rollPlayerDamage` fallback `2 + str*0.45 + weaponPower*0.6`, ~line 287), and
auto-attack exists (`setAutoAttackTarget` ~192, `processAutoAttacks` ~630).
Two things to do:
1. Verify `tryUseSkill` (~line 509) never bails for an empty `right_hand`; if
   any skill definition gates on a weapon, give `DEFAULT_SKILL_IDS.primary` an
   unarmed path (reduced range 1, uses the fallback damage roll).
2. Auto-retaliate: in the monster→player damage path (monster
   combat-controller applying damage to a player), if the player is alive and
   `player.combat.autoAttack` is null, call
   `setAutoAttackTarget(player, monster)`.
Add spec `tests/unit/unarmed-combat.spec.js`: naked player deals ≥1 damage via
primary skill; naked player hit by a monster acquires an autoAttack target and
damages it on the next `processAutoAttacks` tick.

### 1c. Level/exp bar
`src/components/layout/GameHUD.vue` — the exp bar is tiny and overlaps the
health orb. Move it to a PoE-style thin bar spanning the bottom edge of the
screen (below/behind the quickbar, full width, ~6px tall, tooltip with
`XP current/next (percent)`), so it cannot occlude the orbs. Update
`tests/unit/hud-orb-ui.spec.js` if it asserts layout.

### 1d. Orb rendering artifacts
`src/components/hud/HudOrb.vue` + `src/core/hud/wizard-orb-renderer.js`:
- Jaggies: canvas backing store must be `displayedSize × devicePixelRatio`
  (set `canvas.width/height` to `canvasSize * dpr`, scale the ctx), and set
  `ctx.imageSmoothingEnabled = true; ctx.imageSmoothingQuality = 'high'`.
- Dark edges: the circular mask picks up a dark 1px halo from the plate art.
  After compositing, apply the alpha mask with `destination-in` using a circle
  ~1–1.5px smaller in radius than the art edge (or shrink the mask radius by
  `1.25 * dpr`) so the fringe pixels are clipped.
Accept: orbs at HUD size show smooth edges, no black outline, on both 1x and
high-DPI (`preview_resize` or manual check).

## Phase 3 — Skill tree corrections (P0, small-medium)

All in `src/core/passives/verdigris-geometric-tree.js` unless noted.

1. **Naming failure mode** (documented in WIZARD
   `tools/geometric_skilltree/ISSUES.md`): rename origin
   `'Prime Seed Nexus'` → `'Origin'` (in `createMainNode` and the
   `initialTreeState` placeholder in
   `src/components/passives/GeometricSkillTreePane.vue`). Grep the module for
   any other invented terms not present in the WIZARD content pools
   (`NODE_EFFECTS/NOTABLES/KEYSTONES/SIGNS/MASTERIES/GRAND_MASTERIES`) and
   plain-ify them. Log line "geometric resonance" → "loop bonus"; keep pool
   names as-is (they're canonical).
2. **Conduit secondary-stat bias is inverted.** `biasArcAttributes` moves 1
   point from the primary axis to a hard-coded `secondaryByAxis` table entry —
   which is the *far* axis (a conduit hugging the STR axis gains +1 INT).
   Fix: drop the table; the secondary must be the **second-highest axis
   weight at the sampled control point**. In `Conduit.makeOption`, `weights`
   is already computed — pass it to `biasArcAttributes` and pick
   `secondary = sorted(weights)[1]` (keep the existing "only shift if
   primary > 1" rules). Add to
   `tests/unit/verdigris-geometric-tree.spec.js`: for the conduit between
   `8,0`→`9,0` (on/near STR axis, game coords: +q is STR), no option grants
   INT; both options' secondary is DEX or pure STR.
   *(Optional note for the user: same bug exists upstream in WIZARD
   `tools/geometric_skilltree/index.html` — do not fix there in this sprint.)*
3. **Level-scaled points; level 1 starts at 0.**
   - `VerdigrisGeometricTree` constructor takes
     `{ availablePoints }` (no default = 0). `reset()` restores the
     constructor value, not the 123 constant.
   - `GeometricSkillTreePane.vue` (has `game` prop): compute
     `availablePoints = clamp((game?.player?.level ?? 1) - 1, 0, VERDIGRIS_SKILL_TREE_SOURCES.levels)`
     (+ quest points later, currently 0) and pass it in; also re-derive when
     the player levels (watch `game.player.level`, then rebuild or top up
     `points.skill`).
   - `VERDIGRIS_SKILL_TREE_POINTS.skill = 123` stays as the **cap** shown in
     Stats.vue ("X of 123 max").
   - Update `verdigris-geometric-tree.spec.js` (construct with explicit
     points, e.g. 123 for allocation tests; add a test: level-1 → 0 points →
     `isAvailableNode` false everywhere) and `verdigris-skill-tree-ui.spec.js`.
Accept: fresh level-1 guest opens the tree with 0 points and cannot allocate;
naming test passes; conduit bias test passes.
